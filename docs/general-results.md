## rc3 phase-contract correction and failed live validation

Inspection of the unedited rc2 requests/responses showed that one shared schema exposed verdict choices during action selection. The model repeatedly chose an uncertainty verdict while asking to navigate or click, contrary to the host's action contract. rc3 moves that existing constraint into the structured schema: action turns require a null verdict and empty citations and cannot finish. Only after the host has successfully captured all ordered checkpoints does it offer the assessment phase, which cannot invoke browser actions. An action-phase stop leaves the host inconclusive without making a result claim; an assessment-phase stop must explicitly be inconclusive.

The prompt also clarifies that a checkpoint's measurement trigger is not necessarily the next action: the model must first choose permitted input/setup actions based on actual observed values. No fixture action recipe, hidden label, automatic setup, output repair, fallback, retry, or weaker final-evidence check was introduced. Browser authorization, transport, objective predicates, and evaluator grading are unchanged.

All 24 actual rc2 replies are retained as regression fixtures: the six valid opens remain admissible; every one of the 18 premature-claim responses still fails unchanged. Ten new tests check those responses and phase transitions, missing/failed prerequisites, exhausted actions, stopping, and forbidden post-completion browser actions. This is an explicit model-task contract correction on the visible development set, not a blind evaluation or proof of generalization.

## rc4 final bounded correction and completed live validation

- Before any successful page observation, available actions include only operator-authorized navigation actions (or stop). The browser already rejected every interaction on its initial blank page. The runtime does not navigate automatically, select a route, or provide a workflow recipe.
- Assessment citations are constrained to exactly the actual captured checkpoint IDs, with matching minimum/maximum length and uniqueness. Both finishing and abstaining cite that exact set. The host's independent final verdict, citation, screenshot, and trace checks remain unchanged. No missing citation is filled in or bad output repaired.

The prompt explains those general constraints without case-specific answers. Authorization, browser execution, fixture cases, objective predicates and evaluator code remain unchanged.
